## 一、四条设计原则

| # | 原则 | 一句话 |
|---|---|---|
| **P1** | **编码 = 身份，不是描述** | 编号一经分配**永久绑定**；归档只挪目录、编码不变；废弃**留空不回收**；重排属结构性变更，须项目主管拍板 |
| **P2** | **三分离** | 文件名只回答三件事：**段位**（归谁）· **序号**（第几份）· **主题**（是什么） |
| **P3** | **版本只走三个口子** | 迭代版本出现在：**目录**（`v2.0/`）· **头部「迭代版本」字段** · **编码内的 `<VV>` 位**（版本内嵌型命名空间，见 §四）；**不写进 `<主题>`**。原「段分界线」机制**已废弃** |
| **P4** | **命名空间登记制** | 新段位 / 新前缀走「**登记**」而非「改规则」——登记于本文件 §三 / §四 与 `gov-a` §2.2，一次登记全队遵守 |

## 二、编码语法

```
文件名 = <段位缩写>-[<VV>]<序号>_<主题>.md

  <段位缩写> ::= gov | pm | prd | dev | man     段位，2–3 位小写英文（§三 登记）
  <VV>       ::= 两位版本号，仅「版本内嵌型」命名空间带（§四）
  <序号>     ::= a…z | aa…zz                     段位内唯一，只增不复用
  -          ::= 段位与序号之间的固定分隔符
  _          ::= 序号与主题之间的固定分隔符（主题内不得再出现 "_"）
  <主题>     ::= 中文（可夹英文缩写），不提版本 / 日期 / 任务号 / 状态词（§六）
```

**示例**：`dev-h_发布监控页.md` = `dev`（03 开发文档段）+ `h`（段内第 8 份）+ `发布监控页`（主题）。

**排序性**：同段位内先按 `<VV>`、再按 `<序号>` 字典序排序，与视觉顺序一致。

## 七、生命周期与索引同步义务

```
分配 → 使用 → 归档（编码不变，只挪目录，如 `03a`–`03f` → `03_开发文档/归档/`） → 废弃（编码不回收，留空）
```

**分配时三项同步（缺一不可）**：

1. 所属**段 index**（如 `03_开发文档/dev_开发文档.md`）；
2. `gov-a_文档规范.md` **§2.4 完整索引**；
3. 段 index 的「**下一可用**」字段。

> 归档是**一次性**的：文件落入 `v1.0/` / `v2.0/` 后不再跨版本移动；确需改判属结构性变更，须项目主管拍板。

版本清单   ^v\d+\.\d+_需求清单\.md$
