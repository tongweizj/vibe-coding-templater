## 0. 系统概览

| 项 | 内容 |
|---|---|
| **定位** | 英文萨省/多伦多新闻 → 中文待发布文章的**本地自动流水线** |
| **形态** | 三模块串行：**采集 → 智能处理 → 发布**，监控后台全程只读可视化 |
| **技术取向** | 数据只存本地（JSON 文件，零数据库）· Ollama 本地推理（不外发）· cron 调度 · 网页爬虫（无 RSS） |
| **范围** | 覆盖萨省 + 多伦多（后续扩展温哥华），按省级地域标签分类 |
| **解决什么** | 52sask 萨省华人新闻网站「建站初期无流量、无内容」的核心痛点——用全自动流水线稳定供给本地中文资讯 |

**产品数据流**（模块级）：

```
英文新闻源 ──► 【采集】fetch ──► 待选池(new)
                                      │
                                      ▼
             【智能处理】tag 打标聚类 ──► topics(话题/文章)
                          rank 热度评分
                          translate 中文翻译 ──► pending
                                      │
                                      ▼
             【发布】publish ──► published（线上库）
                                      │
                   监控后台全程只读（采集记录 / 池 / 话题 / 翻译）
```

**状态流转**（单一系统）：

```
new ──tagged──► pending ──publish──► published
                  │
                  └──(人工否决)──► rejected
```

## 1. 用户与场景

- **运营者（Max）**：每天花最少精力，获得当日最热的本地话题，自动翻译、定时发布到网站；可随时监控流水线运行、人工否决不宜发布的内容。
- **读者**：生活在草原三省中小城市的华人移民，需要精准、有消费力的本地中文资讯。

### 2.1 采集模块（对应 F1）

**职责**：定时扫描英文新闻源，抓取正文，去重入池。是流水线的**入口**。

| 编号 | 功能需求 | 验收方向 |
|---|---|---|
| FR-C1 | **多源配置加载** | 新闻源以配置驱动，支持启停开关；每源带**双层地域标注**（城市/省级精确值 + 省级标签），供后续排序/翻译分组使用 |
| FR-C2 | **列表页抓取** | 从源站列表页提取新闻链接，仅保留文字新闻（剔除视频/含查询参数的链接） |
| FR-C3 | **非新闻过滤** | 按标题关键词黑名单丢弃订阅、通讯、招聘等非新闻条目 |
| FR-C4 | **详情页解析** | 提取标题、段落正文、发布时间；容器样式变化时容错兼容 |
| FR-C5 | **详情重试** | 正文为空时自动重试（应对源站异步加载） |
| FR-C6 | **URL 哈希去重入池** | 同一 url 只入池一次（幂等），重复抓取自动跳过 |
| FR-C7 | **运行记录埋点** | 每次运行写一份**结构化运行记录**（每源 fetched/new/failed + 总计 + 状态自动推断），供监控后台读取 |
| FR-C8 | **反爬基础防护** | UA 伪装、请求超时、请求间隔限速 |

> **采集范围规划**：萨省 + 多伦多（当前）→ 温哥华（后续，见 `prd02c_采集范围扩展温哥华.md`）。
>
> **运维辅助模式**：`--list-only`（只采列表不抓详情，快速测试）、`--refetch-empty`（补抓池内无正文的存量记录）—— 属工具便利性，不单独列为需求。

### 2.2 智能处理模块（对应 F2-F5）

**职责**：把待选池里的英文原文，变成「有频道、有标签、按事件聚类、按热度排序、已译中文」的待发布内容。是流水线的**核心**。

#### 2.2.1 打频道 + 打标签 + 事件聚类（F2/F3）

| 编号 | 功能需求 | 验收方向 |
|---|---|---|
| FR-P1 | **打固定频道（channel）** | 每篇归入固定频道体系的一类（8 类：移民政策/本地突发/民生服务/天气交通/商业地产/华人社区/教育/医疗）；输出容错匹配，无法归类的跳过 |
| FR-P2 | **打自由标签（tags）** | 每篇产出 3-6 个中文短语标签，与频道解耦，用于文章列表展示 |
| FR-P3 | **事件摘要提炼** | 每篇提炼「一句话事件摘要 + 实体关键词 + 中文城市名」，作为聚类比对与展示用 |
| FR-P4 | **事件级聚类（F3）** | 同频道内，仅当与已有 open 话题相似度达阈值才归并，否则新建——**「宁可新建不误并」**，避免话题膨胀 |
| FR-P5 | **话题/文章判定** | 聚类完成后统一判定：被 ≥2 篇报道的事件为「话题」，单篇仅为「文章」 |
| FR-P6 | **话题全量重算** | 支持清空重建全部话题（复用已有频道/标签，不重复调用模型），用于算法调整后重跑 |

**聚类相似度模型**（产品级约定，详见 `03a_总体设计.md` §4.2）：

```
相似度 = 关键词Jaccard(0.55) + 字符bigramJaccard(0.20) + 地域相似度(0.25)
```

- 地域是**软约束**而非硬过滤：同省同城 1.0 / 同省不同城 0.5 / 跨省 0.0——本地事件因地域差异得以区分，跨省主题因关键词重叠仍可合并。

#### 2.2.2 热度评分（F4）

| 编号 | 功能需求 | 验收方向 |
|---|---|---|
| FR-P7 | **评分公式** | `score = 0.55×媒体数 + 0.30×新鲜度 + 0.15×频道权重`，三项归一化后加权 |
| FR-P8 | **两级打分** | 话题级与文章级分别打分（文章级热度反查所属话题媒体数，单篇=1） |
| FR-P9 | **Top-N 输出** | 输出当日最热 Top10（默认），**按地域均衡**（每个地域独立取前 N，保证各地域内容不偏废） |
| FR-P10 | **频道权重** | 各频道权重可配（移民政策/本地突发更高） |

> **关键取向**：原网站「点击量」多数拿不到，**不作为主依赖**，仅作可选加分项——热度由媒体数 + 新鲜度 + 权重决定。

#### 2.2.3 中文翻译（F5）

| 编号 | 功能需求 | 验收方向 |
|---|---|---|
| FR-P11 | **选题范围** | 翻译对象 = 真话题（被多篇报道）+ 高分单篇，按地域分组每地域取 Top-N，保证每天 ≥10 篇进入 pending |
| FR-P12 | **代表稿选取** | 话题取一名成员作代表稿；无正文跳过、已翻译跳过（幂等） |
| FR-P13 | **英译中** | 面向加拿大华人的新闻语体；标题 + 正文两段式输出 |
| FR-P14 | **写回单一系统** | 翻译结果（`title_cn`/`body_cn`）**直接写回 news**，`status` 置 `pending`（**废弃独立 queue 存储**） |

> **模型分工原则**：量大的用快模型、量小的用质量模型。打频道/标签用快模型；事件摘要与翻译用质量模型（详见 `03a_总体设计.md` §8）。
>
> **历史沿革**：选题范围原为「仅真话题」(稿源 ~2 篇/天)，后依方案 B 扩为「真话题 + 高分单篇」(稿源 ~30 篇/天)，详见 `FR-D1_定时发布开发文档.md` §0/§2（Q7）与 `03e_翻译范围方案B.md`。

#### 2.2.4 编排入口

| 编号 | 功能需求 | 验收方向 |
|---|---|---|
| FR-P15 | **串行编排** | 采集→打标→排名→翻译四步串行，任一步失败即终止（快速暴露问题） |
| FR-P16 | **发布解耦** | 发布环节不在编排链内，可单独调度/暂停（翻译与发布解耦） |

### 2.3 发布模块（对应 F6）

**职责**：把 `pending` 内容发布到线上库。**首版为待重构实现**，完整规格见 `FR-D1_定时发布开发文档.md`。

| 编号 | 功能需求 | 验收方向 |
|---|---|---|
| FR-D1 | **定时发布** | 按节奏从待发布内容中选稿，发布到线上库 |
| FR-D2 | **发布模式三档** | 支持 manual / semi_auto / auto 三档，由配置决定（详见 `03f_发布模式三档.md`） |
| FR-D3 | **幂等发布** | 同一篇不重复发布（幂等键去重） |
| FR-D4 | **前端 API 对接** | 幂等写接口（POST /api/articles，external_id 幂等键 + Bearer token），详见 `03c_前端API发布.md` |
| FR-D5 | **状态推进与回写** | 发布后置 `published`，**并回写 pool**（现状缺陷：不回写导致监控断链，为待修复项） |
| FR-D6 | **地域轮转** | 发布时按地域轮转，保证各地域内容均衡 |
| FR-D7 | **人工否决** | `pending` 可被人工否决为 `rejected`（下一轮跳过） |

> ⚠️ **现状提示（开发主管反馈，2026-09-26）**：首版 `publish.py` 存在已知缺陷——front-matter 用旧字段 `label`（应为 `channel`）、**不回写 pool**、无幂等去重、无前端 API、无发布模式与地域轮转。上述 FR-D2~FR-D6 均为待建项，规格详见 `FR-D1_定时发布开发文档.md`。

### 2.4 监控后台（跨模块，只读可视化）

**职责**：对上述三模块的运行状况做**只读可视化**，让运营者一眼掌握流水线健康度。

| 编号 | 功能需求 | 验收方向 |
|---|---|---|
| FR-M1 | **采集监控** | 展示 fetch 运行历史 + 各源站健康度（成功率）+ 待选池概览与明细（详见 `prd01c_采集监控.md`） |
| FR-M2 | **处理监控** | 展示话题分布（按频道/状态/单篇多篇）+ 话题列表 + 标签统计 |
| FR-M3 | **翻译查看** | 从待选池明细可查看每篇的中文翻译（标题/正文/来源） |
| FR-M4 | **只读约束（首版）** | 首版为纯只读、刷新即读（无 WebSocket、无写操作）；**操作能力（手动触发/发布/否决）由 `prd02a_admin手动操作.md` 在 v2.0 扩展** |

> 监控后台的实现级设计（API 清单、页面结构）见 `03a_总体设计.md` §11。

## 3. 非功能需求

| 项 | 要求 |
|---|---|
| 数据本地化 | 数据只存本地，不上传不外发（翻译走本地 Ollama） |
| 幂等性 | 每条新闻 url 哈希去重，断点可续跑；翻译/发布幂等 |
| 可暂停 | 发布器与翻译解耦，可单独暂停 |
| 零外部依赖 | 除 Ollama 外不依赖第三方 API（NewsAPI 弃用） |
| 可部署 | Windows 开发 → Ubuntu 家庭服务器部署 |
| 可观测 | 每步运行留结构化记录 + 文本日志，供监控与排障 |

## 4. 成功标准

- 每天能稳定产出并发布 **≥ 10 篇**中文新闻（对应 Top10 话题 / 地域均衡）。
- 从英文采集到中文发布**全自动**，人工只需补新闻源 URL、偶尔校准标签、必要时人工否决。
- 运营者可通过监控后台无门槛掌握流水线运行状态。

## 5. 风险与待定

| 风险 | 应对 |
|---|---|
| 爬虫被反爬 / 页面结构变化 | 通用爬虫 + 运行记录告警，源站尽量选稳定的 |
| 服务器访问北美站需代理 | 待确认，配置预留 proxy（见 `prd02b_生产上线.md`） |
| 本地模型翻译质量 | 用质量模型（qwen3:8b）；不达标再换更大模型 |
| 原站点击量拿不到 | 热度不依赖点击量，用媒体数 + 新鲜度 + 权重 |
| 话题膨胀（误并） | 事件级聚类 + 阈值 0.45「宁可新建不误并」 |
