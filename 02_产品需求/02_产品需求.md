## 一、分类说明

`02` 段是**需求文档层**，对应 `gov-a_文档规范.md` 六章的**三段式（功能级）**第一阶段。

**产品经理职责**：

1. 写需求文档（FR 编号 + 验收 + 待拍板清单）。
2. 维护数据模型文档（字段定义、状态机、命名约定）。
3. 定义每个功能的验收标准。
4. **不写实现细节**——模块划分、接口契约、代码结构归 `03` 段（开发主管）。

**协作纪律**：需求文档的「待拍板清单」必须显式列出并给建议，由项目主管拍板（L2 方案级）；未拍板项不得进入开发。

## 三、编码预留说明

`02` 段**分四类**：
- **全局文档** `02<字母>`（段根，现 `02a`，下一可用 `02b`）——跨版本、不属任何产品版本。
- **版本级需求清单** `v<版本号>_需求清单.md`（版本子目录，现 `v1.0/`+`v2.0/`+`v3.0/`）——该版本**全部 FR 的范围界定**（非单一 FR 需求），**不占字母位**。
- **版本需求** `prd<版本><字母>`（版本子目录）——`v1.0/` **暂无**（`prd01b` 移交 03 段、`prd01c` 迁入 `v2.0/`）；`v2.0/` 现有 `prd01c` + `prd02a`~`prd02e`（其中 `prd02a`/`prd02d`/`prd02e` **需求已移 v3.0、文档暂留**）；`v3.0/` 暂无版本需求文档。**下一可用字母 = `prd02f`**。
- **FR 需求文档**（v4.6）`FR-<编码>_<功能名>需求文档.md`——**已与 `02a` 功能编码一一映射**的文档（见 `gov-a` §2.6），**不占字母位**（与字母编号并行）。

> ⚠️ **所属迭代版本以内容为准**（`gov-a` v4.9/v4.10）：`prd01c`（监控后台）→v2.0、`prd02b`（生产上线）→v2.1、`prd02a`/`prd02d`/`prd02e` 需求→v3.0——**编号前缀仅作历史标识，物理归档/改名由项目主管手动执行**。

## 四、与其他分类的关系

```
02 产品需求（做什么、验收什么）  ← 本分类
        │  产品经理产出 FR + 验收
        ▼
03 开发文档（怎么做、决策点）    ← 开发主管据此设计
        │
        ▼
实现代码 + 测试 → 回写 01 项目管理（进度）
```
