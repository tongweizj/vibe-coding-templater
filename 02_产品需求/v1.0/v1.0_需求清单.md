## 1. 选型判据

**唯一判据**：**没有它，「采集 → 智能处理 → 发布」就跑不通，或跑出来的内容不可用。**

据此，v1.0 = **功能链路的"直通主干"**：

- 采集全模块（入口，无源即无内容）
- 智能处理主干（产出「有频道、有标签、按热度排序、已译中文」的内容）
- 发布核心（把内容推上线的自动路径）

**被排除的**一律满足「锦上添花」而非「跑通必需」：

- 需要**人工介入**的（人工确认、否决）→ 依赖操作台 → v2.0
- 需要**可视化/观测**的（监控后台）→ v2.0
- 需要**话题级能力**的（事件聚类、话题判定、话题重算、两级打分）→ v2.0
- 需要**扩量/可配置**的（多地域、频道后台）→ v2.0
- 需要**换环境**的（部署、告警）→ v2.1

## 8. 验收标准（v1.0 完成定义）

1. **全链路自动**：`run_daily.py`（采集→打标→热度→翻译）+ `publish.py`（发布）由 cron 驱动，无人干预连续跑通。
2. **内容产出**：每天稳定产出并发布 **≥ 10 篇**中文新闻（对应 `02a` §4 成功标准）。
3. **可排障**：结构化运行记录 + 文本日志可定位各环节问题（**可视化监控界面属 v2.0**）。
4. **幂等**：重复抓取不重复入池，重复发布不重复上线。
5. **状态一致**：`new → tagged → pending → published` 全链路状态正确回写。

> 完成「能自动跑通」即视为 v1.0 达成；运营者的省力化与人工干预能力、可视化监控（v2.0）、生产环境稳定性（v2.1）由后续版本负责。
>
> ⚠️ **范围变更（2026-09-26 Max 拍板）**：标准 1 中「由 cron 驱动」的真实运行验证**移出 v1.0 → v2.1 `prd02b`**（cron 属生产环境调度，Ubuntu 部署归 v2.1）。v1.0 达成定义 = 全链路能力实证（run_daily 真实数据跑通 + 真实 site 推送 + 幂等，K5a/K5b 已验收）+ 产能达标（translate 每轮 ≥10 篇）；标准 2「每天稳定 ≥10 篇」的持续运行观察随 v2.1 上线进行。
